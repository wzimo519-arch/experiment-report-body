# 运行原理

`school-easier` 是一个小型路由器，不是把网页任务和 Word 任务的所有步骤同时塞进入口。

## 1. 入口路由

`SKILL.md` 只做三件事：

1. 判断输入是否同时具备网页任务或实验报告的必要信息。
2. 选择且只选择一个分支。
3. 规定完成证据、安全边界和汇报方式。

| 场景 | 选择 |
|---|---|
| 页面链接 + 明确题号或任务范围 | `web_task` |
| Word 报告 + 明确正文范围 | `course_experiment` |
| 网页任务后还要填写对应报告 | 先 `web_task`，再 `course_experiment` |

这样路由的好处是上下文更短：处理网页题时不加载 Word 排版经验，处理报告时不加载浏览器提交细节。

## 2. 分支权威文档

入口引用的分支文档是该模式的唯一完整流程：

- `branches/web_task.md` 负责页面侦察、题型识别、答题、提交、异步评阅和最终进度核验。
- `branches/course_experiment.md` 负责报告边界、代码落点、真实运行、截图、原位填写和逐页渲染。

分支之间可以传递真实结果，但不能互相替代。例如网页题通过后，报告分支使用页面和代码的真实输出填写；不能为了报告好看而伪造截图。

## 3. 阶段循环

两个分支都采用 `Plan -> Do -> Check -> Act -> Close`：

| 阶段 | 目的 |
|---|---|
| Plan | 读取真实页面或文档，建立唯一任务清单 |
| Do | 最小范围地作答、运行代码或填写正文 |
| Check | 用页面判分、真实运行输出或渲染页面验证 |
| Act | 只根据失败证据修正，限制重试次数 |
| Close | 保留完成页和原文档，只清理本次创建的中间页 |

这不是固定按钮序列。命令表列出的是能力，例如“定位”“操作”“验证”；实际工具名取决于当前环境。

## 4. 状态优先

每次点击、输入、翻题或切换代码标签后，都重新读取页面状态。原因是：

- 题目卡片和选项可能重新渲染。
- 页面绝对序号会因隐藏控件而变化。
- 代码编辑器可能有多个实例，其中只有一个是当前可见的。
- 评阅是异步的，提交按钮成功不代表代码通过。

因此 skill 要求状态驱动操作，而不是记录一次坐标后连续盲点。

## 5. 完成证据

网页任务至少经过两层验证：

1. 单题结果：选项状态、测试集、单题得分或通过提示。
2. 组级和课程级结果：成绩单分值、课程总进度。

实验报告至少经过两层验证：

1. 内容来源：代码实际运行输出和真实截图。
2. 文档结果：保存后的原文件逐页渲染检查。

只有指定范围全部满足完成证据，入口才允许汇报“全部完成”。

## 6. 经验回流

真实任务暴露的新问题先记录为可复现步骤，再判断是否改变未来决策：

- 多个平台都会遇到的模式，写入对应分支。
- 只在特定产品出现的选择器、弹层或流程，写入 `references/lessons.md`。
- 会改变用户看到的行为或安装方式，写入 `CHANGELOG.md` 和 `README.md`。

这样可以持续升级，同时避免把一次偶发现象写成所有网站都必须遵守的规则。
